# Общий Stop/Retry Budget для AI coding-агентов saymer-alt

**Решение владельца: 14.11.2026.** Действует во всех активных проектах `saymer-alt`: Z AI/ZCode, Codex, Kimi, локальные и CI-агенты. Это правила на выполнение задач, **не** повод сокращать инженерное ТЗ, отключать обязательные тесты или менять безопасность. Более строгие местные STOP-правила сохраняют приоритет.

## Обязательный цикл

1. **Перед экспериментом:** зафиксировать Issue/PR, точный SHA/ABI/toolchain/sysroot, одну проверяемую гипотезу и дешёвый быстрый preflight (синтаксис, компиляция конкретного компонента, минимальный reproducer, тип/версия ABI). Найти готовые PASS в PR/issues до повторения.
2. **Loop Guard = 2:** после **двух одинаковых безрезультатных попыток** при той же ошибке/входах/окружении запрещён третий пустой rerun. Нужны новая проверяемая гипотеза или `BLOCKED`.
3. **Hard Stop = 3:** для **одной технической проблемы** максимум **три попытки исправления ИЛИ три полные тяжёлые сборки/прогона** (release/LTO, SDK, QEMU E2E, широкий CI), **что наступит раньше**. Счётчик общий для локального хоста и CI, повторных сессий, агентов и веток. Перезапуск терминала/смена агента не сбрасывает бюджет. Каждая полная сборка считается попыткой для этого же блокера; отдельные дешёвые статические проверки допускаются до STOP. Доказанный инфраструктурный сбой можно повторить только с конкретной причиной и с учётом лимита.
4. **При лимите — STOP:** безопасно завершить текущую операцию, не начинать четвёртую попытку и не обходить лимит новым названием задачи. Сохранить запись `попытка → гипотеза → конкретное изменение → тест → результат`, первую полезную ошибку, ссылки на лог/артефакты, оставшиеся риски, до трёх альтернатив. Сообщить владельцу, получить **отдельный owner GO** на новый ограниченный цикл.
5. **Не повторять PASS:** использовать прежний результат, только если совпадают source SHA, toolchain/sysroot, ABI/архитектура, зависимости, asset digest и scope проверки. Если вход изменился — назвать точную дельту и необходимый gate; прошлый PASS не переносится на новый SHA.
6. **Краткий checkpoint:** если нет прогресса, уже делались дорогие эксперименты или возник новый класс ошибок, показать `SHA | PASS | BLOCKED | attempts/heavy builds | next cheapest step | owner GO needed`. Нельзя расходовать промоквоту ради исчерпания. Токены указывать только по реальной телеметрии, иначе `NOT_AVAILABLE`.

## Safety / DoD

- Экономия токенов не отменяет регрессионные, security, негативные, ABI, QEMU/hardware проверки: при исчерпанном бюджете обязательный gate остаётся `NOT_TESTED/BLOCKED`, а не условно зелёным.
- Merge, release, delete, публикация IPK, обновление live-устройств/VPS и небезопасные изменения требуют самостоятельного owner GO. Правила бюджетирования **не** дают этих разрешений.
- `CI PASS != QEMU PASS != FIELD PASS != PUBLISHED`; документировать состояние точно.
- Корневой `AGENTS.md` репозитория должен содержать **одну краткую ссылку**, без копирования этого документа. Подробности читать по запросу для затронутой задачи.
- Для KAS дополнительно действует локальный [agent-token-efficiency](https://github.com/saymer-alt/keenetic-auto-setup/blob/main/docs/agent-token-efficiency.md); для Entware см. его локальную политику. Локальные более строгие ограничения и запреты всегда в силе.
